openxava / documentación / Desplegar en producción como WAR ejecutable

Desde OpenXava 8.0 tus aplicaciones son aplicaciones Spring Boot. Esto significa que el archivo WAR que generas con Maven es un WAR ejecutable, puedes ejecutarlo directamente con Java sin necesitar un servidor de aplicaciones externo. Esta es una alternativa a desplegar en Tomcat, más sencilla e ideal para muchos entornos de producción.

Cuándo usar un WAR ejecutable frente a Tomcat

Usa el WAR ejecutable si solo tienes una aplicación, o si tienes pensado desplegar en Docker o Kubernetes, ya que el WAR ejecutable es un artefacto autocontenido fácil de containerizar. Usa Tomcat en cambio si quieres tener varias aplicaciones en el mismo servidor, o si ya tienes un Tomcat instalado y quieres reutilizarlo.

Generar el WAR

Abre un terminal, o usa el terminal de tu IDE, y ejecuta Maven desde la carpeta raíz de tu proyecto:

$ cd facturacion
$ mvn clean package

Esto genera facturacion.war (o tunombreaplicacion.war) dentro de la carpeta target de tu proyecto.

Ejecutar el WAR

Asegúrate de tener Java 17 o superior instalado y JAVA_HOME configurado. Luego, simplemente ejecuta el WAR con Java:

$ java -jar facturacion.war

Tu aplicación ya está funcionando. Usa tu navegador para acceder a http://localhost:8080/facturacion.

Ejecutar como servicio en segundo plano

En un servidor de producción normalmente quieres ejecutar la aplicación en segundo plano y mantenerla funcionando después de cerrar la sesión. Una forma sencilla es usar nohup en Linux/Mac:

$ nohup java -jar facturacion.war &

Para una configuración más robusta considera usar un gestor de servicios como systemd o un gestor de procesos como Supervisor para gestionar el ciclo de vida de tu aplicación.

Configurar contra la base de datos de producción

Por defecto tu aplicación va contra la misma base de datos que usas en desarrollo, la que tienes definida con las propiedades spring.datasource.* en application.properties de tu proyecto. La mayoría de las veces vas a querer una base de datos diferente para producción. Puedes sobrescribir la configuración de la base de datos sin modificar el WAR usando la configuración externalizada de Spring Boot.

Coloca un archivo application.properties en la misma carpeta donde ejecutas el WAR y se cargará automáticamente:

spring.datasource.url=jdbc:hsqldb:hsql://dbserver:1999
spring.datasource.username=facturacion
spring.datasource.password=afj30
spring.datasource.driver-class-name=org.hsqldb.jdbcDriver

Alternativamente, puedes pasar las propiedades como argumentos de línea de comandos:

$ java -jar facturacion.war \
  --spring.datasource.url=jdbc:hsqldb:hsql://dbserver:1999 \
  --spring.datasource.username=facturacion \
  --spring.datasource.password=afj30

O usar variables de entorno:

$ export SPRING_DATASOURCE_URL=jdbc:hsqldb:hsql://dbserver:1999
$ export SPRING_DATASOURCE_USERNAME=facturacion
$ export SPRING_DATASOURCE_PASSWORD=afj30
$ java -jar facturacion.war

Estos enfoques te permiten usar el mismo WAR contra diferentes bases de datos en distintos entornos sin tener que recompilar.
