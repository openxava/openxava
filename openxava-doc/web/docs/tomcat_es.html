openxava / documentación / Desplegar en producción con Tomcat

Si estás usando OpenXava 7.x o anterior mira las instrucciones para OpenXava 7

Puedes desplegar tus aplicaciones OpenXava en cualquier servidor de aplicaciones Java con soporte de Jakarta Servlet 6.1 o superior. Para esta guía vamos a usar Apache Tomcat para desplegar tu aplicación OpenXava. Tomcat es el servidor de aplicaciones Java más usado y robusto, ideal para entornos de producción. Las aplicaciones OpenXava son aplicaciones Spring Boot, así que además de ejecutarlas directamente con su Tomcat embebido, también puedes generar un WAR estándar y desplegarlo en un Tomcat externo, tal como has hecho siempre.

Cuándo usar Tomcat frente a un WAR ejecutable

Desde OpenXava 8.0 tienes dos formas de ejecutar tu aplicación en producción: desplegar el WAR en un Tomcat externo, como se explica en esta guía, o ejecutar el WAR directamente con java -jar como un WAR ejecutable. Usa Tomcat si quieres tener varias aplicaciones en el mismo servidor, o si ya tienes un Tomcat instalado y quieres reutilizarlo. Usa el WAR ejecutable si solo tienes una aplicación, o si tienes pensado desplegar en Docker o Kubernetes, ya que el WAR ejecutable es un artefacto autocontenido fácil de containerizar.

Descargar e instalar Tomcat

Descarga Tomcat 11 desde Apache. Descomprime el Tomcat en una carpeta de tu elección. Ve a la carpeta webapps y borra las carpetas que hay dentro: docs, examples, host-manager, manager y ROOT. Son aplicaciones de ejemplo y administración que no deberías tener en un sistema de producción.

Crear y desplegar el WAR

Para desplegar tu aplicación en Tomcat has de crear un archivo WAR desde tu proyecto. Abre un terminal, o usa el terminal de tu IDE, y ejecuta Maven desde la carpeta raíz de tu proyecto:

$ cd facturacion
$ mvn clean package

Después coge el archivo facturacion.war (o tunombreaplicacion.war) de la carpeta target de tu proyecto y cópialo en la carpeta webapps de tu Tomcat. Tu aplicación ya está desplegada.

Ejecutar Tomcat

Para arrancar tu Tomcat, con Windows pulsa el botón de Inicio, teclea cmd y pulsa INTRO, entonces:

set JAVA_HOME=C:\Program Files\Java\jdk-17.0.9
cd tomcat-11.0.23\bin
startup

Con Linux/Mac:

export JAVA_HOME=/usr/lib/jvm/java-17-openjdk
cd tomcat-11.0.23/bin
./startup.sh

Por supuesto, ajusta las rutas para tus propios directorios del Tomcat y Java.

¡Enhorabuena! Tu aplicación ya está funcionando en producción, ya puedes usar tu navegador para probarla.

Configurar contra la base de datos de producción

Por defecto tu aplicación va contra la misma base de datos que usas en desarrollo, la que tienes definida con las propiedades spring.datasource.* en application.properties de tu proyecto. La mayoría de las veces vas a querer una base de datos diferente para producción. Para este caso debes usar el mecanismo clásico de Tomcat, añadir tu fuente de datos al context.xml situado en la carpeta conf de tu Tomcat.

<?xml version="1.0" encoding="UTF-8"?>

<Context>

    <Resource name="jdbc/facturacionDS" auth="Container" type="javax.sql.DataSource"
        maxTotal="20" maxIdle="5" maxWaitMillis="10000"
        username="facturacion" password="afj30" driverClassName="org.hsqldb.jdbcDriver"
        url="jdbc:hsqldb:hsql://dbserver:1999"/>

</Context>

Usamos facturacionDS como nombre de fuente de datos, el mismo nombre JNDI declarado para la fuente de datos por defecto en el persistence.xml de tu proyecto.
