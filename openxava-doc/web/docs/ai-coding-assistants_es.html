Por qué OpenXava funciona bien con asistentes de codificación IA

OpenXava funciona extraordinariamente bien con asistentes y agentes de codificación IA como GitHub Copilot, Cursor, Claude Code, Devin, Codex, JetBrains Junie, y otros. Hay varias razones para ello:

  • Basado en estándares Java: OpenXava se basa en estándares Java bien conocidos como JPA, Bean Validation y anotaciones estándar. Los modelos de IA han sido entrenados extensamente con estas tecnologías y las comprenden en profundidad.
  • Más de 20 años de historia open source: OpenXava es un proyecto de código abierto desde 2004. Esto significa que hay dos décadas de código fuente, documentación, discusiones en foros, tutoriales y aplicaciones de ejemplo disponibles públicamente en internet, todo lo cual ha sido ingerido por los conjuntos de datos de entrenamiento de IA.
  • Convención sobre configuración: El enfoque de OpenXava de generar toda la interfaz de usuario a partir de clases Java anotadas es sencillo de entender para la IA. La IA solo necesita producir una entidad JPA con unas pocas anotaciones, y OpenXava se encarga del resto.
  • Código mínimo repetitivo: Gracias a la integración con Lombok y al estilo declarativo de OpenXava, el código que la IA necesita generar es conciso y basado en patrones, exactamente el tipo de código en el que la IA destaca.

Puedes ver esto en acción en el Curso con IA, donde se construye una aplicación de negocio completa usando un agente IA con mínima intervención manual.

Optimizaciones para agentes IA

OpenXava incluye optimizaciones específicas para hacer que los asistentes de codificación IA sean aún más efectivos. Estas optimizaciones proporcionan a los agentes IA contexto específico del proyecto y ejemplos de código real, para que produzcan código OpenXava correcto desde el primer intento.

AGENTS.md

Cada nuevo proyecto OpenXava incluye un archivo AGENTS.md en la raíz del proyecto. Es un archivo Markdown especial que los asistentes de codificación IA leen automáticamente para entender las convenciones y reglas de tu proyecto. La mayoría de IDEs modernos con IA (Cursor, GitHub Copilot, Devin, etc.) reconocen este archivo y lo usan como contexto al generar código.

El archivo AGENTS.md incluido con los proyectos OpenXava contiene:

  • Instrucciones de Jakarta EE: Indica a la IA que use siempre imports jakarta.* (persistence, validation, servlet, inject, etc.) y nunca javax.*, aunque sus datos de entrenamiento contengan código OpenXava más antiguo con javax.*.
  • Convenciones de entidades JPA: Cómo usar Lombok, reglas de visibilidad de campos y patrones de anotaciones correctos.
  • Patrones maestro-detalle: Instrucciones para usar @ElementCollection y @Embeddable en lugar de @OneToMany para colecciones de detalle.
  • Convenciones de acciones: Reglas sobre cómo definir acciones en controllers.xml y crear clases de acción sin modificar la entidad.
  • Convenciones de pruebas: Cómo escribir pruebas JUnit usando ModuleTestBase, incluyendo el requisito de llamar a login() como primera línea.
  • Convenciones de cuadros de mando: Instrucciones para revisar la documentación y dónde colocar las clases del cuadro de mando.
  • Referencias a ejemplos de código: Dirigiendo a la IA a consultar ejemplos de código real en GitHub como guía.

Esto significa que cuando le pides a un agente IA que "cree una entidad Cliente" o "escriba una prueba para el módulo Factura", seguirá las convenciones de OpenXava automáticamente.

Ejemplos de código en GitHub

Además de AGENTS.md, el archivo apunta al agente IA a ejemplos de código real alojados en el repositorio GitHub de OpenXava:

  • Ejemplos de pruebas: Pruebas JUnit reales del conjunto de pruebas de OpenXava, mostrando cómo probar diferentes tipos de módulos: openxavatest/.../tests/bymodule
  • Acciones disponibles: La lista completa de acciones en los controladores de OpenXava, para que la IA sepa qué acciones puede usar en las pruebas: default-controllers.xml

Como los ejemplos se referencian por URL, no hay nada que generar ni mantener en tu proyecto, y la IA siempre ve los ejemplos de la última versión.

Cómo funciona en conjunto

Cuando un asistente de codificación IA abre tu proyecto, lee AGENTS.md para aprender las reglas del proyecto. Cuando necesita generar una prueba o entender cómo funciona OpenXava, sigue los enlaces a los ejemplos de código en GitHub. Esta combinación de reglas y ejemplos resulta en una generación de código mucho más precisa.

Proyectos nuevos

Los proyectos creados con OpenXava 7.7 o posterior ya incluyen todo lo necesario: el archivo AGENTS.md está en la raíz del proyecto y listo para usar. No se requiere configuración adicional.

Añadir soporte IA a proyectos existentes

Si tu proyecto aún no tiene un archivo AGENTS.md, puedes añadir soporte para asistentes de codificación IA manualmente:

Descarga el archivo AGENTS.md del repositorio GitHub de OpenXava y colócalo en la raíz de tu proyecto:

https://github.com/openxava/openxava/blob/master/openxava-archetype/AGENTS.md

Después de descargarlo, edita el archivo para reemplazar los marcadores del arquetipo con los valores reales de tu proyecto:

  • Reemplaza ${package} con tu paquete base (p. ej. com.tuempresa)
  • Reemplaza ${artifactId} con el nombre de tu proyecto (p. ej. tuapp)

Por ejemplo, si tu paquete es com.miempresa y tu artefacto es facturacion, cambia:

package ${package}.${artifactId}.model;

por:

package com.miempresa.facturacion.model;

Eso es todo. No hacen falta cambios en tu pom.xml.

Personalizar AGENTS.md

El archivo AGENTS.md es totalmente personalizable. Puedes y deberías editarlo para incluir convenciones específicas de tu proyecto. Por ejemplo:

  • Añadir convenciones de nombres para tus entidades y paquetes.
  • Documentar reglas de negocio específicas que la IA debería seguir.
  • Incluir patrones para acciones personalizadas o validadores usados en tu proyecto.
  • Añadir referencias a tu propio código de ejemplo.

Cuanto más específico y detallado sea tu AGENTS.md, mejor entenderá el asistente de codificación IA tu proyecto y generará código que se ajuste a tus estándares. Piensa en ello como documentación de incorporación, no para un nuevo desarrollador, sino para un agente IA.

OpenXava 7.7

En OpenXava 7.7 los ejemplos de código para agentes IA no se enlazaban desde GitHub, sino que se desempaquetaban en una carpeta local .xava en la raíz del proyecto, generada a partir del artefacto Maven openxava-agents-examples. Este artefacto no existe en OpenXava 8.0, donde los ejemplos se referencian directamente en GitHub.

Si tu proyecto fue creado con OpenXava 7.7, contiene una carpeta .xava/agents/ con ejemplos de pruebas y definiciones de controladores, y una ejecución unpack-agents-examples del maven-dependency-plugin en su pom.xml que regenera la carpeta en cada compilación. Al actualizar a OpenXava 8.0 debes eliminar esa ejecución, borrar la carpeta .xava y actualizar tu AGENTS.md. Consulta la guía de migración para más detalles.

Si te quedas en OpenXava 7.7, ejecuta mvn package para generar la carpeta .xava, y no la añadas a .gitignore, porque la mayoría de asistentes de codificación IA solo buscan archivos que están dentro del proyecto y que no estén ignorados por Git.
