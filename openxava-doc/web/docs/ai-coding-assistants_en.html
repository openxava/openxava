Why OpenXava works well with AI coding assistants

OpenXava works remarkably well with AI coding assistants and agents such as GitHub Copilot, Cursor, Claude Code, Devin, Codex, JetBrains Junie, and others. There are several reasons for this:

  • Built on Java standards: OpenXava is based on well-known Java standards like JPA, Bean Validation, and standard annotations. AI models have been extensively trained on these technologies and understand them deeply.
  • Over 20 years of open source history: OpenXava has been an open source project since 2004. This means there are two decades of source code, documentation, forum discussions, tutorials, and example applications publicly available on the internet—all of which has been ingested by AI training datasets.
  • Convention over configuration: OpenXava's approach of generating the entire user interface from annotated Java classes is straightforward for AI to understand. The AI only needs to produce a JPA entity with a few annotations, and OpenXava takes care of the rest.
  • Minimal boilerplate: Thanks to Lombok integration and OpenXava's declarative style, the code that AI needs to generate is concise and pattern-based—exactly the kind of code AI excels at producing.

You can see this in action in the Course with AI, where a complete business application is built using an AI agent with minimal manual intervention.

Optimizations for AI agents

OpenXava includes specific optimizations to make AI coding assistants even more effective. These optimizations provide AI agents with project-specific context and real code examples, so they produce correct OpenXava code from the very first attempt.

AGENTS.md

Every new OpenXava project includes an AGENTS.md file in the project root. This is a special Markdown file that AI coding assistants automatically read to understand the conventions and rules of your project. Most modern AI-powered IDEs (Cursor, GitHub Copilot, Devin, etc.) recognize this file and use it as context when generating code.

The AGENTS.md file included with OpenXava projects contains:

  • Jakarta EE instructions: Directs the AI to always use jakarta.* imports (persistence, validation, servlet, inject, etc.) and never javax.*, even though its training data contains older OpenXava code with javax.*.
  • JPA entity conventions: How to use Lombok, field visibility rules, and correct annotation patterns.
  • Master-detail patterns: Instructions to use @ElementCollection and @Embeddable instead of @OneToMany for detail collections.
  • Actions conventions: Rules on how to define actions in controllers.xml and create action classes without modifying the entity.
  • Test conventions: How to write JUnit tests using ModuleTestBase, including the requirement to call login() as the first line.
  • Dashboards conventions: Instructions to review the documentation and where to place the dashboard classes.
  • References to code examples: Directing the AI to look at real code examples on GitHub for guidance.

This means that when you ask an AI agent to "create a Customer entity" or "write a test for the Invoice module," it will follow OpenXava conventions automatically.

Code examples on GitHub

In addition to AGENTS.md, the file points the AI agent to real code examples hosted in the OpenXava GitHub repository:

  • Test examples: Real JUnit tests from the OpenXava test suite, showing how to test different types of modules: openxavatest/.../tests/bymodule
  • Available actions: The complete list of actions in OpenXava controllers, so the AI knows which actions it can use in tests: default-controllers.xml

Since the examples are referenced by URL, there is nothing to generate or maintain in your project, and the AI always sees the examples of the latest version.

How it works together

When an AI coding assistant opens your project, it reads AGENTS.md to learn the project rules. When it needs to generate a test or understand how OpenXava works, it follows the links to the code examples on GitHub. This combination of rules and examples results in much more accurate code generation.

New projects

Projects created with OpenXava 7.7 or later already include everything needed: the AGENTS.md file is in the project root and ready to use. No additional setup is required.

Adding AI support to existing projects

If your project does not have an AGENTS.md file yet, you can add AI coding assistant support manually:

Download the AGENTS.md file from the OpenXava GitHub repository and place it in your project root:

https://github.com/openxava/openxava/blob/master/openxava-archetype/AGENTS.md

After downloading, edit the file to replace the archetype placeholders with your actual project values:

  • Replace ${package} with your base package (e.g. com.yourcompany)
  • Replace ${artifactId} with your project name (e.g. yourapp)

For example, if your package is com.mycompany and your artifact is invoicing, change:

package ${package}.${artifactId}.model;

to:

package com.mycompany.invoicing.model;

That is all. No changes to your pom.xml are needed.

Customizing AGENTS.md

The AGENTS.md file is fully customizable. You can and should edit it to include conventions specific to your project. For example:

  • Add naming conventions for your entities and packages.
  • Document specific business rules that the AI should follow.
  • Include patterns for custom actions or validators used in your project.
  • Add references to your own example code.

The more specific and detailed your AGENTS.md is, the better the AI coding assistant will understand your project and generate code that fits your standards. Think of it as onboarding documentation—not for a new developer, but for an AI agent.

OpenXava 7.7

In OpenXava 7.7 the code examples for AI agents were not linked from GitHub but unpacked into a local .xava folder in the project root, generated from the openxava-agents-examples Maven artifact. This artifact does not exist in OpenXava 8.0, where the examples are referenced directly on GitHub instead.

If your project was created with OpenXava 7.7, it contains a .xava/agents/ folder with test examples and controller definitions, and an unpack-agents-examples execution of the maven-dependency-plugin in its pom.xml that regenerates the folder on each build. When you upgrade to OpenXava 8.0 you must remove that execution, delete the .xava folder and update your AGENTS.md. See the migration guide for details.

If you stay on OpenXava 7.7, run mvn package to generate the .xava folder, and do not add it to .gitignore, because most AI coding assistants only search files that are inside the project and not ignored by Git.
